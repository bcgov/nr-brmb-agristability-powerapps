Release Window Quick Start

1) Pipeline

Action: Release app/solution to target stage (Test or Prod).

Success Pipeline stage completed and artifacts deployed.

2) Config + Bindings

Action: Update stage config file and run post-deploy script.

Watch Any replace-with-* value will fail script execution.

3) Push

Action: Script runs npx power-apps push.

Success Push exits with code 0 and app is reachable.

4) Validation

Action: Smoke test dashboard, deep links, and enrolment pages.

Blocker If dashboard or deep links fail, verify core config row immediately.

Roles and Handoffs

Stage Primary Role Output
Pipeline release Release manager / DevOps Target environment artifact deployment complete
Post-deploy bindings App operator Data sources rebound to target environment connections
Config verification Business app admin Active core config row validated
Smoke testing QA / app operator Go/no-go outcome

Prerequisites

  • pac installed and authenticated to target environment.
  • Node.js + npm installed.
  • Repo checked out locally with dependencies installed.
  • Access to target connector connectionId values.
  • Permission to add/rebind Power Apps data sources.
  • New/updated flows must be in a solution and discoverable via npx power-apps list-flows in the target stage.

What the Post-Deploy Script Does

  1. pac code init -n <appName> -env <environmentId>
  2. For each data source in stage config: pac code add-data-source -a <apiId> -c <connectionId>
  3. Injects Dataverse table mappings from dataverseTableMappings into power.config.json
  4. Resolves flow IDs in the stage with npx power-apps list-flows --json and binds them with npx power-apps add-flow -f <workflowId>
  5. npm.cmd run build (unless -SkipBuild)
  6. npx.cmd power-apps push

Validation Checklist (Go/No-Go)

  • Dashboard page loads with embedded report.
  • Deep links open target app and route correctly.
  • Enrolment list loads and variance flags appear correctly.
  • Core links open expected records (if configured).
  • No placeholder values remain in target stage config.

Common Failures and Fast Fixes

Script fails with placeholder value

Update scripts/powerapps-deploy.config.json for the target stage. Replace all replace-with-* values.

Logic Flows/Power BI connection IDs not auto-synced

Expected in some environments if sharedConnectionId is not present in power.config.json. Enter those IDs manually in stage config.

PAC cannot find the target environment by GUID

Usually wrong tenant/account is active in PAC. Re-auth and select by URL:

pac auth list
  pac auth create --deviceCode
  pac org select --environment https://aff-brmb-crm-test.crm3.dynamics.com/

Flow still skipped by script

The flow is not yet discoverable as a solution cloud flow invokable from Power Apps in that stage. Verify with:

npx power-apps list-flows --search "<flow name>" --json --no-color

Deep links fail after successful push

Verify active core config has valid vsi_coreenvironmentid and vsi_tenantid.

Schema file shows old environment ID

Do not manually edit schema files. Re-run target environment binding/post-deploy steps.
