Enrollment App Deployment Runbook

Repository: nr-brmb-agristability-powerapps/enrollment app

Generated: 2026-06-18

1. Purpose

This runbook defines the full deployment process for Test and Prod, including pipeline release, required Dataverse core configuration fields, and the post-deploy PowerShell scripts used to bind environment-specific connectors and push the app.

2. High-Level Release Flow

  1. Deploy with your standard pipeline release into the target environment (Test or Prod).
  2. On a deployment workstation/agent authenticated to the target Power Platform environment, run post-deploy script steps to bind data sources and push.
  3. Validate core configuration values in Dataverse.
  4. Run smoke tests (dashboard, deep links, enrolment pages).
The values visible in .power/schemas are generated connector metadata and will differ per environment. Do not manually edit these schema files.

3. Prerequisites

  • Power Platform CLI (pac) installed and authenticated to the target tenant/environment.
  • Node.js + npm installed.
  • Repo cloned and dependencies installed (npm ci or npm install).
  • Permission to add/rebind Power Apps data sources in target environment.
  • Environment-specific connector connection IDs available (FARMS, Dataverse, Logic Flows, Power BI).

4. Pipeline Release Instructions

4.1 Release to target stage

  1. Run your normal pipeline release for the target stage (Test or Prod).
  2. Confirm the app/solution artifact deployment is successful in release logs.
  3. Do not stop at this point. Pipeline release does not finalize local code bindings for all connectors.

4.2 Post-release handoff

After pipeline success, execute the scripts in this repo to complete target-environment connector binding and app push.

6. Script Files

  • scripts/powerapps-deploy.config.json: stage-specific environment IDs and datasource connection IDs.
  • scripts/sync-deploy-config-from-powerconfig.ps1: copies discovered values from power.config.json into a selected stage in deploy config.
  • scripts/post-deploy-powerapps.ps1: runs pac code init, pac code add-data-source, optional build, and npx power-apps push.

7. Step-by-Step Execution

7.1 Open terminal at repo root

cd "c:\agristability\nr-brmb-agristability-powerapps\enrollment app"

7.2 Review stage config placeholders

Open scripts/powerapps-deploy.config.json and confirm target stage values are populated. Any value starting with replace-with- will fail fast in script execution.

7.3 Optional: auto-sync discovered values from power.config.json

After running pac code init / datasource binding in the target environment, use:

.\scripts\sync-deploy-config-from-powerconfig.ps1 -Stage test -PowerConfigPath .\power.config.json -DeployConfigPath .\scripts\powerapps-deploy.config.json -AllowOverwrite

This can auto-fill environment ID and connector IDs where sharedConnectionId is present in power.config.json.

7.4 Run full post-deploy workflow

.\scripts\post-deploy-powerapps.ps1 -Stage test -ConfigPath .\scripts\powerapps-deploy.config.json

For Prod:

.\scripts\post-deploy-powerapps.ps1 -Stage prod -ConfigPath .\scripts\powerapps-deploy.config.json

7.5 Skip build option (if build already validated in pipeline)

.\scripts\post-deploy-powerapps.ps1 -Stage prod -ConfigPath .\scripts\powerapps-deploy.config.json -SkipBuild

8. What the post-deploy script executes

  1. pac code init -n <appName> -env <environmentId>
  2. For each datasource: pac code add-data-source -a <apiId> -c <connectionId> (plus optional table/dataset parameters if configured)
  3. npm.cmd run build (unless -SkipBuild)
  4. npx.cmd power-apps push

9. Post-Deployment Validation Checklist

  1. Dashboard loads (Power BI embed works in target stage).
  2. Deep links open target app URL with correct environment and tenant context.
  3. Enrolment grid loads and variance highlighting behaves as expected.
  4. Core links navigate correctly (if vsi_coreenvironmenturl is set).
  5. No script placeholder errors remain for target stage config.

10. Troubleshooting

Issue: placeholder value error

Update scripts/powerapps-deploy.config.json for the target stage. Any replace-with-* value is intentionally blocked.

Issue: missing shared connection IDs for Logic Flows or Power BI

Some connection references in power.config.json may not include sharedConnectionId. Fill those connection IDs manually in deploy config.

Issue: schema still shows old environment GUID

Expected until connectors are rebound in target environment. Re-run post-deploy process for the target stage.

Issue: deep links fail

Check active core config row has valid vsi_coreenvironmentid and vsi_tenantid.

11. Recommended Operational Practice

  1. Keep this runbook and scripts versioned with the app code.
  2. Treat .power/schemas and power.config.json as environment-generated artifacts.
  3. Use stage-specific config + script execution after every pipeline promotion.
